# cifmi

[![Crates.io](https://img.shields.io/crates/v/cifmi?logo=rust&color=264323)](https://crates.io/crates/cifmi)
[![PyPI](https://img.shields.io/pypi/v/cifmi?logo=pypi&logoColor=white&color=3775A9)](https://pypi.org/project/cifmi/)
[![npm](https://img.shields.io/npm/v/cifmi?logo=npm&color=CB3837)](https://www.npmjs.com/package/cifmi)

cifmi reads CIF files into crystal structures. It is written in Rust,
with Python and Node.js bindings, and gives the same structure for the same
file in every runtime. Install it with `cargo add cifmi`, `pip install cifmi`
or `npm install cifmi`.

A `Structure` holds:

- the cell as the file gives it, and its vectors with c along z and a in the
  xz plane;
- the space group as the file names it, and where the operations came from;
- the sites of the asymmetric unit: the file's atom rows, those on one
  position (up to symmetry) merged into one site, each with its species,
  occupancies, oxidation states and isotropic displacement parameters;
- the symmetry operations;
- every atom of the unit cell those operations generate from the sites;
- diagnostics: what the file left open or got wrong, reported rather than
  fixed quietly.

```rust
use cifmi::{read_cif, CifOptions};

let structure = read_cif("quartz.cif", &CifOptions::default())?;
for atom in &structure.atoms {
    let site = &structure.sites[atom.site];
    println!("{} at {:?}", site.label, atom.position);
}
for diagnostic in &structure.diagnostics {
    eprintln!("{}: {}", diagnostic.kind.code(), diagnostic.message);
}
```

The Python package reads the same structure:

```python
import cifmi

structure = cifmi.read_cif("quartz.cif")
for atom in structure.atoms:
    site = structure.sites[atom.site]
    print(site.label, atom.fractional)
for diagnostic in structure.diagnostics:
    print(diagnostic.kind, diagnostic.message)
```

The Node.js package, from [`node/`](node/), returns it as plain objects that
survive JSON and structured cloning: `readCifFile` reads a file off the main
thread, and `readCifStr` reads text.

## The reading

Every file is read one way, by crystallographic rules, and what the file
leaves open is settled by those rules and reported, never chosen quietly:
standard CIF 1.1 and 2.0 syntax with case-insensitive and DDLm data names;
listed operations checked to form a group, or the settings a space-group
name admits, settled by the atoms and the declared formula; sites snapped
onto their special positions where they cannot be split atoms; listings
already expanded read once; deuterium kept; B from anisotropic U when no
isotropic value is listed. There is no alternative reading and no fallback:
a file cifmi cannot read is an error with the reason. The
[design](docs/design.md) lists every rule and the evidence for it.

## Development

From the repository root:

```sh
cargo test
python -m pip install -e ".[test]"
python -m pytest tests
npm --prefix node install
npm --prefix node run build
npm --prefix node test
```

The unit tests sit next to the code; [`tests/reading.rs`](tests/reading.rs)
reads the [COD fixtures](tests/README.md) and small constructed files.

`src/spacegroups.rs` is generated by `tools/generate_spacegroups.py` from
gemmi's table of settings; regenerate it with an interpreter that has gemmi
and numpy, then review the diff.
[CONTRIBUTING.md](CONTRIBUTING.md) describes the checks and the release flow.
